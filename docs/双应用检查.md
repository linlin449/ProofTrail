# 从签发端到知识发布站

这套演示包含两个 FastAPI 应用：应用 A 是 ProofTrail 来源工作台；应用 B 是 Knowledge Publisher，模拟知识发布工具在生成私有预览前的来源检查。应用 B 没有发行者私钥、签发接口或凭证库；只接收原文与凭证，使用自己的 Registry 配置和 Python SDK 查询可信合约。

## 本地演示

```powershell
uv run python examples/two_apps.py
```

- 应用 A：http://127.0.0.1:8775/
- 应用 B：http://127.0.0.1:8776/

两个应用的本地模式在同一进程中共用内存 EVM 提供者，但持有不同的 Registry 对象。共享锁只用于避免测试链的并发访问冲突。这证明应用 B 的验证不依赖 A 的 HTTP API 或数据库，不是两个独立外网部署的证据。默认 8765 的旧演示与这里是不同的本地链，不要混用其凭证。

1. 在应用 A 签发一份笔记，下载凭证 JSON，并保留原文。
2. 在应用 B 导入 JSON，将未改变的原文粘贴进去，点击“检查并生成预览”。检查通过后显示私有预览；不会公开发布。
3. 改一个字或换行：原预览立即清除，再检查时内容完整性失败。
4. 恢复原文，在应用 A 撤销当前凭证，再在 B 检查：撤销项失败，预览被拒绝。
5. 每次使用前重新读取状态。通过检查是该次查询时的结果，不是永久有效认证。

## 真实 Monad 的独立运行

先完成并核对测试网部署记录，将地址作为可信配置，而不是从投稿凭证中自动选择合约。A 与 B 可以分别部署；B 无需知道 A 的网址。

```powershell
uv run python -m prooftrail consumer --contract <核对过的合约地址> --port 8776
```

公开部署可显式指定 `--host 0.0.0.0`，并由反向代理提供 HTTPS。配置 `PROOFTRAIL_ALLOWED_HOSTS` 为自己的实际域名；不要使用 `*`。B 不需要 `PROOFTRAIL_PRIVATE_KEY`。原文会发送给 B 的验证服务，但不保存到数据库或链上；部署方仍需检查代理日志与监控是否记录请求内容。

## API

`POST /api/assess` 接受 `{ "content": "原文", "bundle": { ...完整凭证... } }`。

- `eligibleForPreview` 只在全部来源验证通过时为 true。
- `verification` 含签名、内容、证明、登记和撤销的分项结果。
- `preview` 在失败或链上不可用时为 null；成功时仅供当前页面渲染。
- 所有投稿都必须符合严格 schema；正文最多 50,000 字符、请求最多 4 MB。

服务不会渲染输入为 HTML。预览不是事实审查、版权判断、现实身份认证或正式公开发布行为。

## 自动证据

`uv run pytest tests/test_consumer.py -q` 使用真实本地 EVM 验证：签发后清空 A 的凭证库，B 仍然通过；篡改失败；链上撤销后 B 的结果改变；B 没有签发或凭证列表接口。另验证请求上限、Host 检查、JavaScript MIME 与链失联时的健康状态。

外部 Monad 钱包、不同主机和真实开发者采用仍需部署后验收，不用这套本地演示替代。
