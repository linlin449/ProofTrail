# 中文操作与接入指南

## 本地检查

运行 `uv run python -m prooftrail serve`，打开 http://127.0.0.1:8765 。页面标注本地 EVM；使用虚构研究笔记演示。

1. 在“签发凭证”输入标题、应用、模型声明和原文。
2. 默认登记一份；“批量登记与版本设置”可选择 4 或 16 份。其余副本是自动添加编号的测试内容，不是伪造真实用户。
3. 点击“签发并登记凭证”，检查真实交易 Gas 与摊销 Gas。本地耗时不能作为 Monad 网络性能。
4. 下载 JSON 凭证，点击“验证这份内容”。所有分项通过才为有效。
5. 点击“模拟一次内容篡改”，再验证。签名仍能通过，内容完整性失败，便于说明不同证据的含义。
6. 恢复原文，再验证。点击“撤销当前凭证”，在页面确认；再查验证结果，撤销状态失败。

输入变化后会清除旧验证结果，避免把旧的通过状态误认为当前内容有效。本地链重启后旧凭证不能继续验证。

## 独立 Python 消费者（应用 B）

`examples/consumer.py` 不调用签发服务，只使用公开协议与可信 Monad RPC。原文读文件的原始字节，支持任意文件媒体，不会自动改换行。

```powershell
uv run python examples/consumer.py note.txt receipt.json --contract YOUR_VERIFIED_CONTRACT
```

退出码 0 表示有效，2 表示不通过或无法确认。RPC 无法使用、字节码错误等配置错误会抛出异常，不能静默通过。

## 签发 CLI（应用 A）

使用本机环境变量配置专用测试私钥，CLI 不接受把私钥放入命令参数。不要发送密钥到聊天，也不要使用有真实资产的账户。

```powershell
uv run prooftrail issue note.txt --title "研究笔记" --contract YOUR_VERIFIED_CONTRACT --output receipt.json
```

该命令在 Monad 测试网发送 1 笔登记交易并生成 JSON 凭证。钱包余额必须包含测试 MON。输出路径已存在时拒绝覆盖。

## API

- `GET /api/info`：可信域与运行模式。
- `POST /api/verify`：`content` + `bundle`，返回 valid/invalid/unavailable 与逐项结果。
- `POST /api/prepare`：生成 EIP-712 声明供浏览器钱包签名，不持有私钥。
- `POST /api/batch`：校验签名并返回凭证证明与待发送交易数据，不发送交易。
- `POST /api/revoke-transaction`：返回调用撤销函数的数据，不发送交易。
- `POST /api/demo/issue` / `demo/revoke`：仅本地回环、本地测试链演示。

无需外部 CDN 的中文 API 参考页面位于 `/docs`，精确 schema 可从 `/openapi.json` 下载。安全策略只允许本站脚本。

在线模式输入正文会发送给验证/prepare 服务；敏感内容应使用本地 SDK。服务器不保存正文；这不等于端到端加密。
