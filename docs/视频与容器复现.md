## 双应用容器准备

Dockerfile 采用两个阶段：用固定 uv 版本按锁文件安装非 editable 包，再只复制运行环境到非 root 运行镜像。构建上下文使用白名单，排除私钥、环境文件、截图与本机依赖目录。运行默认仅为 Monad 钱包模式，不开放服务端发行签名。

**Linux 镜像与真实网络双容器已验证**：2026-10-03 实际构建完成；非 root、只读、断网容器完成本地 SDK 与 HTTP 检查。随后两个独立 Monad 容器读取公网 RPC，消费端原文/篡改/撤销检查通过，服务端签名返回 403，均 healthy 且无签名私钥。证据：`artifacts/monad-container-probe.json`。这仍是本机映射端口，不冒充外网托管。

本地复现安装检查（不连接 Monad）：

```powershell
docker build -t prooftrail:review .
$proofTrailSmokePath = (Resolve-Path scripts/container_smoke.py).Path
docker run --rm --read-only --network none --cap-drop ALL --security-opt no-new-privileges --entrypoint python --mount "type=bind,source=$proofTrailSmokePath,target=/tmp/probe.py,readonly" prooftrail:review /tmp/probe.py
```

证据：`artifacts/container-smoke.json`、`container-http-probe.json`、`container-build-record.json`。HTTP 探针在执行写入前强制检查 local 模式，拒绝外部网络写入。本轮临时服务容器已清理；`prooftrail:review` 镜像留在本机，既有本地页面服务未更改。

```powershell
$env:PROOFTRAIL_CONTRACT = '0xd4c01FEdb19eF081AAF3c6814316d8CeF7579Cd7'
docker compose config
docker compose up --build
```

compose 在回环地址映射 A 到 8765、B 到 8776。两个容器分别读取真实 Monad，不共享内存链或发行库。运行文件系统只读、删除额外 capabilities；不配置私钥。这里尚未提供域名或 HTTPS，在线托管必须再配置并从外网验收。

注意：Python 程序不会自动读取 `.env`；Docker Compose 本身支持 `.env` 插值。这里只传 RPC、合约和允许的 Host 三项公开配置，不传 `PROOFTRAIL_PRIVATE_KEY`。占位地址仅供检查配置语法，不能用来假称已部署。

uv 安装方式依据 [uv 官方 Docker 指南](https://docs.astral.sh/uv/guides/integration/docker/)。
