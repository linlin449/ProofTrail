更新：2026-10-03，北京时间。目标是可供评审真实运行、复现并独立验证的完整项目；未获得用户最终确认，不提交比赛。

## 产品定位

AI 应用 A 签发内容后，应用 B 可以在不信任 A 的 API、也不信任 ProofTrail 数据库的情况下检查签名、原文和链上生命周期。核心差异：可移植凭证 + 批量锚定降低逐条写入成本 + 分项验证 + 独立 SDK + 撤销。

首个用户：需要展示 AI 辅助内容来源的开发者、研究工具与知识发布应用。首个场景：研究助手输出一份笔记，独立发布站验证笔记，发现编辑后内容不匹配，发行者撤销错误版本。

## 评审标准对应策略

- 技术执行：签名域隔离、严格 schema、链上发行者授权、撤销、过期、RPC 失败闭合、攻击测试。
- 设计与体验：用一条凭证的验证轨迹讲清楚问题；开发者可复制少量代码即可接入；中文文档和英文凭证兼容。
- 原创性：重点展示跨应用可移植性与批量成本；不声称首创通用 provenance 或符合完整 C2PA。
- 用户与市场：给出明确用户、竞争替代方式、接入门槛；制作两个独立集成示例；真实外部用户反馈需用户协助联系，不虚构。
- 牵引与后续：SDK API 清楚、开放协议；准备集成指南和反馈表。若无真实用户，坦诚写“尚无外部采用”。
