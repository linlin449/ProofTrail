# 用户获取、定位与评审说明

## 首批用户和场景

面向 Python AI 应用开发者：研究笔记生成器、团队知识库与内容发布工具。接收方希望在不依赖发行平台 API 的情况下检查来源声明与撤销状态。首个场景是研究笔记从应用 A 流入应用 B，编辑后检查失败，错误版本撤销。

当前没有真实外部用户、收入或市场规模证据。不会用内部测试副本冒充采用量。

## 接入与反馈计划

1. 发布可复现 SDK 与“研究助手 → 发布检查”例子，帮助开发者本地跑通。
2. 提供短接入指南，向用户授权联系的真实开发者收集反馈；未经授权不代发消息。
3. 近期目标是一位真实开发者完成接入，记录接入耗时、首张凭证验证、下载携带与撤销检查的实际体验。
4. 根据反馈先改进接口和错误状态，再评估托管验证/索引服务。

拟测量指标：从安装到首次有效验证的时间、跨应用验证成功率、批量摊销成本、撤销后状态同步时间。未经测量，不填成功率与采用数量。

## 相邻方案与取舍

| 方案 | 作用 | ProofTrail 的取舍 |
|---|---|---|
| 平台数据库/API | 向发行平台查询是否发布过 | 可移植凭证与公开链上根降低发行 API 持续依赖；仍需信任发行者身份 |
| 独立签名文件 | 验证签署者和字节完整性 | 增加公开登记与可查询撤销，同时引入网络依赖和成本 |
| C2PA Content Credentials | manifest、签名、内容绑定与验证规范 | v1 是 EIP-712 JSON sidecar；不是完整 C2PA，也不能宣称替代全部能力 |

C2PA 的相关能力依据其[官方技术规范](https://spec.c2pa.org/specifications/specifications/2.2/specs/C2PA_Specification.html)。ProofTrail 侧重 Python 应用可组合的 Monad 凭证生命周期；媒体生态兼容需要进一步研究。

## Monad 提供的价值

公共合约承载批次根与撤销记录，让不同应用查询共享生命周期。每批一笔根登记，每份携带 O(log n) 证明。这是协议结构，不是对未经实测网络吞吐量的承诺。

本地 benchmark 与真实 Monad 测试分别保存。测试网已完成 1/4/16/32 实际批量登记，每批 88,261 Gas；32 条均摊 2,758.15625 Gas。原始回执在 `artifacts/monad-acceptance.json`，这是一轮登记成本样本，不能推断吞吐量或最终性。
