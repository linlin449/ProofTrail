# 在线发布与公开源码

公开 GitHub 仓库：[linlin449/ProofTrail](https://github.com/linlin449/ProofTrail)。比赛提交状态与产品发布状态独立：可以发布真实可用产品，但未经用户确认不执行比赛最终提交。

## 已准备的 Render 免费部署

仓库根目录 `render.yaml` 定义两个 Docker Web Service：

- prooftrail-issuer：钱包签发工作台与验证 API，Monad 模式，服务端不签名。
- prooftrail-consumer：独立 Knowledge Publisher，固定同一可信合约，直接读取 Monad。

两者均指定 free、Singapore、8765、`/health`；不自动跟随每次提交部署。只包含公开的 RPC 和真实合约地址，不配置私钥、数据库或收费附加资源。实际 HTTPS URL 由 Render 创建服务后分配，不能把拟定名称冒充已上线地址。

依据：[Blueprint 配置](https://render.com/docs/blueprint-spec)、[Docker 支持](https://render.com/docs/docker)、[默认域名变量](https://render.com/docs/environment-variables)。运行时在没有手工配置允许 Host 的情况下只添加 Render 给本服务分配的域名，仍拒绝其他应用的 Host；显式配置优先。对应自动测试通过。

## 账号与部署步骤

1. 用户登录或注册 Render。公开源码已准备好，不需要把测试签名私钥交给托管平台。
2. 使用 Blueprint 从公开仓库读取 `render.yaml`，先检查两个服务都为 free、没有秘密值或附加收费资源，再创建。
3. 如果使用手动 Web Service，可选择 Public Git Repository，填写此公开仓库 URL。Docker Command 使用 `render.yaml` 的对应命令，端口 8765，复制公开 RPC/合约环境变量；无需授权读取其他私人仓库。
4. 等服务部署成功，分别核对 health、真实链 ID、可信合约、JS/CSS、正文通过/篡改拒绝/撤销拒绝、独立 SDK 与钱包操作。
5. 保存实际 URL、部署 commit、浏览器截图和外部访问检查；再更新 README 与参赛材料。最终比赛提交仍需用户确认。

账号登录、任何新增 GitHub 授权或条款接受由用户完成；已有 GitHub 登录不会自动创建 Render 身份。目前尚无已验证的外网产品 URL。

## 免费实例的实际限制

按 [Render 免费服务说明](https://render.com/docs/free)，空闲 15 分钟会休眠，再次访问启动约需一分钟；工作区共享免费实例时数，多个实例会共同消耗。没有付费计划或常驻可用性声明。项目不依赖服务端凭证库，重启不会清除 Monad 上的登记/撤销；下载的 JSON 仍可由独立 SDK 验证。生产稳定托管应由用户选择预算与平台。
