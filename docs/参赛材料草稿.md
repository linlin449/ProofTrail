## 项目名称与一句话

**ProofTrail** — Portable AI provenance receipts, independently verifiable on Monad.

## English project description

AI outputs travel between applications, but their provenance and lifecycle often remain tied to the original platform. ProofTrail gives Python builders a portable JSON receipt: an issuer signs the original content hash and constrained metadata using EIP-712; a sorted-pair Merkle root anchors a batch to a registry; another application verifies the receipt with its own trusted chain and contract configuration.

The prototype includes a Python SDK and CLI, a Chinese issuer workbench, and a separate Knowledge Publisher consumer. The consumer checks signatures, byte integrity, inclusion proofs, expiration, issuer-bound registration and current revocation without querying the issuer's receipt database. A failed or unavailable verification prevents a private preview. Neither application treats provenance as proof of factual accuracy, copyright or real-world identity.

The Solidity registry has no administrator or upgrade mechanism. It is deployed on Monad testnet, chain 10143, at `0xd4c01FEdb19eF081AAF3c6814316d8CeF7579Cd7`, with exact-match source verification on Sourcify. Actual 1, 4, 16 and 32 receipt batches each used one registration transaction and 88,261 gas in this run. The 32-item batch amortized registration to 2,758.15625 gas per receipt. Raw transaction records are included; this is not a throughput, finality or dollar-cost claim. Seventy automated tests and an independent Python/ethers protocol vector check cover the current implementation.

Current stage: working Monad testnet prototype, with separate issuer and consumer processes running locally against the public chain. Issuer revocation and namespace isolation are verified with actual transactions. Source is public at https://github.com/linlin449/ProofTrail and a clean clone has been checked. Public application hosting and final wallet-flow/video review are pending. Synthetic-narration pitch and technical review drafts are available. No external adoption or competition submission is claimed.

## Why Monad

The project uses Monad's public EVM registry as the shared lifecycle layer between applications. Only batch roots and issuer revocations are registered; content stays off-chain. The testnet deployment demonstrates interoperable Ethereum signing and Python tooling, batch registration and independent live-state reads. This evidence supports the working integration; it does not establish a measured performance advantage over other networks.
