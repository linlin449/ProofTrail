INDEPENDENT VERIFICATION

一个 JSON 包，
一条独立验证路径。

固定可信网络与合约，
不要把凭证里的地址自动当作可信配置。

Python / 独立消费者
from prooftrail import ReceiptBundle, verify_receipt
from prooftrail.chain import Registry

registry = Registry.monad(RPC_URL, TRUSTED_CONTRACT)
bundle = ReceiptBundle.model_validate_json(receipt_json)
result = verify_receipt(original_bytes, bundle, registry)

接口与返回状态

GET /api/info可信域、合约地址、运行模式
GET /api/example公开合成原文 + 凭证；无验证结论，其他可信域为 404
POST /api/verify原文 content + 凭证 bundle → 分项验证
POST /api/prepare内容 + 元数据 + issuer → 待签署 EIP-712
POST /api/batchreceipts 数组 → 凭证包 + 待发交易
POST /api/revoke-transactionreceiptId → 待发撤销交易
GET /api/transactions/{hash}pending 或实际交易回执
POST /api/demo/issue仅本机、本地 EVM 演示
POST /api/demo/revoke仅本机、本地 EVM 演示

valid：所有证据通过。invalid：至少一项明确失败。unavailable：离线检查没有失败，但当前链上状态无法读取。

结果只描述检查时刻的快照。撤销状态会改变，发布时应重新验证。请求最多 4 MB，原文最多 50,000 字符，Web API 一批最多 64 张；SDK 与合约一批最多 4096 张。精确 schema 可下载 OpenAPI JSON。

协议约束

原始字节 SHA-256；固定元数据字段 title、mediaType、model、application，按 key 排序后紧凑 UTF-8 JSON。无任意字段、浮点或静默内容归一化。

使用 ProofTrail v1 EIP-712 域隔离链与合约。receiptId 为签名摘要，叶子为 keccak256(receiptId)，内部节点对排序哈希对做 Keccak。

model 是发行者声明。协议不证明实际模型执行、现实身份、版权或事实正确性。

verify / request shape
{
  "content": "原始内容文本，包括原来的换行",
  "bundle": { "...": "下载的完整 JSON 凭证包" }
}

此代码块仅说明请求结构，不是有效凭证；不要替换或省略下载包里的字段。
